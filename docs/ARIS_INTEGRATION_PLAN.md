# ARIS 借鉴增强计划

## 结论

PaperPilot 不直接接入整套 ARIS，也不切换到 Claude Code。

采用方式是：**借鉴 ARIS 中适合每日论文雷达的工程模式，按模块吸收进 PaperPilot。**

当前 PaperPilot 主线保持不变：

```text
arXiv -> BM25 + bge-m3 -> candidates.json -> initial review.json -> enriched.json -> final review.json -> Obsidian 日报
```

ARIS 增强只解决三个问题：

1. 让工作流更稳定，减少 Codex 每次执行时的上下文漂移。
2. 让读过的论文、反馈、idea 能长期积累。
3. 让 Top 论文摘要更厚，但不每天全量读 PDF。

## 不引入的 ARIS 能力

| 不引入 | 原因 |
|---|---|
| Claude Code hooks | 当前只使用 Codex |
| cross-model review | 每日论文推荐不需要双模型审稿 |
| `/research-pipeline` 全套流程 | 目标是论文雷达，不是自动完成研究项目 |
| 实验队列/GPU 调度 | 与每日论文筛选无关 |
| 自动写论文、rebuttal、slides | 后续研究工作流可单独考虑 |
| Feishu/Slack 通知 | 当前 Obsidian 是主要阅读入口 |

## 借鉴模块总览

| 阶段 | ARIS 可借鉴内容 | PaperPilot 落点 | 优先级 |
|---|---|---|---|
| A1 | `AGENT_GUIDE.md` 和 artifact contract | 固定 Codex 执行协议 | 高 |
| A2 | Research Wiki | 本地论文记忆与关系图 | 高 |
| A3 | DeepXiv 渐进阅读 | Top 论文 brief/head/section enrichment | 高 |
| A4 | paper verification | 多源检索后的论文真实性校验 | 中 |
| A5 | meta-optimize | 每周基于反馈优化 prompt/规则 | 中 |

## A1：新增 PaperPilot Agent Guide

目标：给 Codex 一个稳定、短小、可复用的执行入口，避免每次自动化都重新解释项目。

新增文件：

```text
/Users/hym/PycharmProjects/PaperPilot/AGENT_GUIDE.md
```

建议内容：

```markdown
# PaperPilot Agent Guide

## Goal

Generate a daily paper recommendation note for Yiming Huang.

## Canonical Paths

- Project: `/Users/hym/PycharmProjects/PaperPilot`
- Obsidian output: `/Users/hym/Library/CloudStorage/OneDrive-std.uestc.edu.cn/Obsidian/3-PaperFlow`

## Workflow

1. Run `scripts/run_candidate_pipeline.sh`.
2. Read `runs/YYYY-MM-DD/candidates.json`.
3. Write initial `runs/YYYY-MM-DD/review.json` following `config/review.schema.json`.
4. Optionally run `scripts/enrich_top_papers.py --date YYYY-MM-DD --top-n 3`, then update `review.json`.
5. Run `scripts/render_daily_note.py --date YYYY-MM-DD`.

## Non-negotiables

- Do not write caches, state, logs, or models into Obsidian.
- Only write readable Markdown notes into Obsidian.
- Daily prose is generated by Codex; Markdown layout is generated by Python.
- `source_basis` must state whether summaries come from `title+abstract`, `html`, `pdf`, or `html+pdf`.
```

验收：

- Codex 自动化 prompt 可以压缩为“按 `AGENT_GUIDE.md` 跑今天日报”。
- 新人或未来会话能在 1 分钟内理解项目边界。

## A2：Research Wiki 简化版

目标：把 PaperPilot 从“每日去重器”升级成“会积累的研究记忆”。

不照搬完整 ARIS 四实体系统。PaperPilot 先只做三个实体：

| 实体 | 目录 | 用途 |
|---|---|---|
| Paper | `state/paper-memory/papers/` | 记录读过、推荐过、跳过的论文 |
| Topic | `state/paper-memory/topics/` | 记录长期兴趣方向 |
| Edge | `state/paper-memory/edges.jsonl` | 记录论文和主题、论文和论文之间的关系 |

建议结构：

```text
state/paper-memory/
├── index.md
├── query_pack.md
├── papers/
│   └── arxiv-2605-12823.md
├── topics/
│   ├── ai4science.md
│   ├── topological-deep-learning.md
│   └── molecular-dynamics.md
└── edges.jsonl
```

Paper 页面字段：

```markdown
---
type: paper-memory
canonical_id: arxiv:2605.12823
title: ...
url: ...
first_seen: 2026-05-15
last_seen: 2026-05-15
status: read | save | later | skip | not_relevant | pending
source_basis: title+abstract
tags:
  - AI4Science
---

# Paper Title

## One-line Thesis

## Why It Matters

## Reusable Ideas

## User Feedback

## Connections
```

边格式：

```jsonl
{"from":"paper:arxiv-2605-12823","to":"topic:ai4science","type":"relevant_to","evidence":"recommended as must_read on 2026-05-15"}
{"from":"paper:arxiv-2605-12823","to":"topic:higher-order-supervision","type":"inspires","evidence":"HVP matching as high-order supervision"}
```

使用方式：

1. 每次渲染日报后，把 `must_read` 和有用户反馈的论文写入 memory。
2. 每次评审前读取 `query_pack.md`，压缩进 Codex prompt。
3. `not_relevant` 和 `skip` 也要写入，作为负反馈。

验收：

- 同一主题下能看到历史推荐过的关键论文。
- Codex 评审能引用“你过去保存/跳过过的模式”。
- `query_pack.md` 控制在 8000 字符以内。

## A3：Top 论文渐进阅读

目标：让日报更厚，但不每天全量读 PDF。

分层策略：

| 层级 | 输入 | 输出 | 触发条件 |
|---|---|---|---|
| L0 | title + abstract | 当前 `deep_dives` | 默认 |
| L1 | arXiv HTML / Abs page | 更准确的方法、实验、局限 | Top 3 |
| L2 | PDF text | section excerpt / fallback context | HTML 不可用时的 Top 论文 fallback |
| L3 | section-level reading | 单独读 Methods/Experiments/Limitations | 需要核查具体问题 |

新增脚本建议：

```text
scripts/enrich_top_papers.py
```

输入：

```text
runs/YYYY-MM-DD/candidates.json
runs/YYYY-MM-DD/review.json
```

输出：

```text
runs/YYYY-MM-DD/enriched.json
```

`enriched.json` 建议字段：

```json
{
  "date": "2026-05-15",
  "papers": [
    {
      "canonical_id": "arxiv:2605.12823",
      "source_basis": "html 或 pdf",
      "sections": {
        "abstract": "...",
        "introduction": "...",
        "methods": "...",
        "experiments": "...",
        "limitations": "..."
      },
      "fetch_status": "ok"
    }
  ]
}
```

Codex 评审规则：

1. 如果有 `enriched.json`，`deep_dives` 优先基于 enrichment。
2. 如果没有 enrichment，`source_basis` 必须保持 `title+abstract`。
3. 不确定的实验细节必须写进 `questions_to_check`，不能补脑。

验收：

- Top 3 论文优先使用 HTML；HTML 不可用时用 PDF text fallback；都不可用才回落到 abstract。
- 每日总耗时可控。
- 不下载全量候选 PDF。

## A4：多源论文校验

目标：未来加入 Semantic Scholar、OpenAlex、Exa、Gemini 或 web search 后，避免假论文、错 DOI、错 arXiv ID 进入日报。

当前 arXiv API 来源可以暂不校验，因为结构化 metadata 已经足够可靠。

新增脚本建议：

```text
scripts/verify_papers.py
```

校验顺序：

1. arXiv ID。
2. DOI / CrossRef。
3. Semantic Scholar title fuzzy match。
4. normalized title fallback。

候选字段：

```json
{
  "canonical_id": "arxiv:2605.12823",
  "verification": {
    "status": "verified",
    "via": "arxiv",
    "checked_at": "2026-05-15T09:00:00Z"
  }
}
```

输出规则：

| 状态 | 处理 |
|---|---|
| `verified` | 可正常推荐 |
| `unverified` | 不能进入必读，只能放入待核查 |
| `verify_pending` | 保留但降权 |
| `conflict` | 标红写入日志，不渲染到 Obsidian |

验收：

- 非 arXiv 来源不会无验证进入 Top 推荐。
- 校验失败不会导致整次日报失败。
- 日报中能看到待核查提示。

## A5：每周 Meta Optimize

目标：让推荐系统根据真实反馈变好，而不是靠人工反复改 prompt。

输入：

```text
state/paper-feedback.jsonl
logs/*.log
runs/*/candidates.json
runs/*/review.json
```

新增脚本建议：

```text
scripts/analyze_recommendation_feedback.py
```

输出：

```text
runs/weekly/YYYY-WW/recommendation-drift-report.md
```

分析内容：

| 指标 | 用途 |
|---|---|
| `read/save` 最高频标签 | 增强兴趣画像 |
| `not_relevant` 最高频标签 | 增加负关键词或类目规则 |
| 被跳过但反复出现的标题模式 | 调整 `category_policy` |
| must_read 中实际 read 比例 | 衡量推荐精度 |
| embedding 分数高但人工跳过 | 调整 query 或阈值 |

建议输出格式：

```markdown
# Weekly Recommendation Drift Report

## Summary

## Positive Signals

## Negative Signals

## Proposed Config Changes

## Changes Not Applied
```

规则：

1. 只提出建议，不自动改配置。
2. 每条建议必须引用具体反馈记录。
3. 数据少于 10 条反馈时，只报告观察，不建议改规则。

验收：

- 每周能看到推荐偏差。
- 能解释为什么要调关键词或过滤规则。
- 不因一两条反馈过拟合。

## 实施顺序

| 顺序 | 任务 | 预计改动 | 风险 |
|---:|---|---|---|
| 1 | 新增 `AGENT_GUIDE.md` | 文档 | 低 |
| 2 | 新增 paper memory 写入脚本 | `scripts/update_paper_memory.py` | 中 |
| 3 | 在评审 prompt 中读取 `query_pack.md` | prompt + runner | 中 |
| 4 | 新增 Top 论文 HTML/PDF enrichment | `scripts/enrich_top_papers.py` | 中 |
| 5 | 后续接多源校验 | `scripts/verify_papers.py` | 中 |
| 6 | 每周 feedback report | `scripts/analyze_recommendation_feedback.py` | 低 |

## 与当前主计划的关系

当前主计划仍是 PaperPilot 的 source of truth。

本文件只是增强路线：

- 不改变当前目录分离原则。
- 不把模型、state、logs 写进 Obsidian。
- 不要求安装 Claude Code。
- 不要求安装 ARIS。
- 不改变 `review.json -> render_daily_note.py -> Obsidian` 的边界。
