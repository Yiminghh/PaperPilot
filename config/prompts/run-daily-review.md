# PaperPilot Daily Review Prompt

You are running the local PaperPilot daily review. Runtime paths are defined in `config/paper-daily-config.yaml`.

Read:

- `AGENT_GUIDE.md`
- `runs/YYYY-MM-DD/candidates.json`
- `runs/YYYY-MM-DD/enriched.json` if it exists
- `config/interest-profile.yaml`
- `config/negative-keywords.yaml`
- `state/paper-feedback.jsonl`
- `state/paper-memory/query_pack.md` if it exists
- recent readable notes under `paths.daily_notes_dir`

Config boundary:

- `config/interest-profile.yaml` contains only positive interests and query expansion.
- `config/negative-keywords.yaml` contains only hard excludes and soft downweight terms.

Write only:

- `runs/YYYY-MM-DD/review.json`

Requirements:

1. The JSON must satisfy `config/review.schema.json`.
2. Do not write the final Markdown note directly.
3. Rank papers for Yiming Huang's interests: topological deep learning, higher-order graph learning, graph generation, molecular/RNA AI4Science, graph/foundation models, and LLMs for scientific discovery.
4. Exclude or strongly downweight quantum computing/information/protocol papers. Quantum chemistry can be kept only when clearly tied to molecular ML or AI4Science.
5. Avoid generic abstract summaries. Explain why the paper is or is not worth reading.
6. Separate paper claims from your inference.
7. Keep must-read papers to 1-5 items.
8. Add `deep_dives` for the top 3-5 must-read papers.
9. If `runs/YYYY-MM-DD/enriched.json` exists, use it for `deep_dives` and set each `source_basis` from the enrichment record.
10. If no enrichment exists for a paper, `deep_dives` are summary-level. Set `source_basis` to `title+abstract` and do not imply that the full PDF was read.
11. Do not promote unverified non-arXiv papers to must-read. If a candidate has `verification.status != verified`, mention the uncertainty and put it in `later` or `skip`.
12. Every paper in `candidates.json` must appear exactly once in one of `must_read`, `worth_reading`, `later`, or `skip`; this is how `state/seen-papers.txt` avoids resurfacing already reviewed candidates.
13. Each deep dive must include TL;DR, Chinese summary, problem, method, core innovations, evidence, limitations, relevance, reusable ideas, and questions to check.
14. Keep Obsidian readability in mind: write compact but substantive Chinese paragraphs, not one-line placeholders.

Suggested daily sequence:

1. Run `scripts/run_candidate_pipeline.sh`.
2. Read `state/paper-memory/query_pack.md` if it exists.
3. Produce an initial `review.json` with ranked `must_read`.
4. Run `python scripts/enrich_top_papers.py --date YYYY-MM-DD --top-n 3`.
5. Re-read `enriched.json` and update `review.json` deep dives.
6. Run `python scripts/render_daily_note.py --date YYYY-MM-DD`.

After writing `review.json`, the Markdown note must be generated by:

```bash
python scripts/render_daily_note.py --date YYYY-MM-DD
```
